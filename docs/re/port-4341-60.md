# Port 157.0.4341.46 -> 157.0.4341.60

A patch of the same line (no public PDB: the symbol server has none for .60).
On .60 the signature search placed 298 of 301 entries; three were not placed,
which stood down the native split and the features that share its entries
(features available 0x76). Every RVA of `offsets.h` is now the one the
signatures placed on .60 (the DLL's `[resolve]` log), the three were found by
hand, and `signatures.g.h` is re-signed from .60.

| entry | .46 | .60 | why the signature missed |
|---|---|---|---|
| View_GetVisible | 0x10052b2 | 0x1088592 | same `mov al,[rcx+1D8h]; ret`; the function moved and the next one changed. Verified: MultiContentsView_CloseSplitView calls it at +0xf in both builds; 1015 callers on .46, 1013 on .60 |
| EdgeOperatorDelete | 0x371d540 | 0x37ba400 | the same one-instruction thunk (`jmp` to Edge's free); the functions after it were reordered, so it now sits right before EdgeOperatorNew. Its target has the same body as .46's (75 instructions) and 2114 callers in both builds; a caller whose opening is byte-identical in both builds calls it at the same displacement |
| BrowserView_tabstrip | 0x297f684 | 0x29c9064 | same `[rcx+668h]`, `[rax+5D0h]`; the next function changed. Only match of its bytes, 11 callers as before, among them the function just before it at the same place |

The hex RVAs some `offsets.h` comments name (functions that hold an entry, a
`jne` target, a vtable) are updated to .60 too.

Struct offsets (`off` namespace) are unchanged: every function and site entry
reads the same field displacements in its first 0x180 bytes on .46 and .60.
