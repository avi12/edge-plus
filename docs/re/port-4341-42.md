# Porting the offsets: 156.0.4314.58 -> 157.0.4341.42

A new line of Edge, ported with **no public PDB** for 157 (the symbol server
still answered 404). The DLL's signature fallback stood every feature down on
157, as designed (`docs/future-proofing.md`): 116 of 295 entries had an
unchanged body, 114 were found but changed, 33 not found.

## How

1. The resolver logs, on any other build, where each entry was found
   (`[resolve] X: found at ...`, and `... changed its code at ...` for one it
   turned down). One run in a throwaway Edge 157 gave the work list: the 156
   RVA, the scanner's 157 candidate and its verdict per entry.
2. `offsets.h` was split into eight slices (functions by banner, struct
   offsets in three parts), each read by hand in both builds: the 156 side
   with the PDB, the 157 side by instruction shape, callers, callees, strings
   and vtables. Every value, including unchanged ones, got a 157 value with its
   evidence.
3. The values were merged, `kVersion*` bumped, the signature table re-signed
   from 157 (`New-SignatureTable.ps1`) and the panel's pinned build regenerated.

## What moved

- `views::View` lost 8 bytes at its end (`View_size` 0x338 -> 0x330) and one
  vtable slot above +0x130: most fields of View subclasses moved by -8
  (MultiContentsView, BrowserView, ContentsWebView, the find bar, the split
  controls) and their high vtable slots by -8.
- `views::Label` moved -8 up to its RenderText, then grew by 0x20: its text now
  sits in the Label (+0x398), its requested colour at +0x3d0, its allocation is
  0x4c8. Its vtable is one slot shorter.
- `Tab` moved the other way (+8: controller, title, layout controller).
- `ContentsContainerView` grew by 16, so `CCV_*` and the
  EdgeContentsContainerView size kept their values.
- String ids shifted (the ⋯ button's is 0x477f); command ids did not.

## Code changes, not just numbers

- **Live preview**: 157's capture driver inlines `StopCapture` into
  `UpdateCaptureState` (twice, cold part) and `OnCooldownEnded`, calling the
  capturer's `Stop` directly. `live_preview.h` now also hooks `Stop` and, while
  a card is open, returns past the rest of an inlined copy (its bytes are
  checked first) from those four call sites only.
- **base::i18n::IsRTL** is no longer a `jmp` thunk; `ICUIsRTL` is called
  directly, so the entry names it.
- **Ordinals**: the scanner placed two "unchanged" entries on the wrong one of
  several identical copies, by their rank in address order, which 157's linker
  changed: `UTF8ToUTF16` on UTF16ToUTF8's wrapper (the find bar's own titles
  came out garbled) and `WebContentsImpl_ForEachRenderFrameHost` on
  RenderFrameHostImpl's. Their bodies differ only in masked call targets, so
  the body check passed. Fixed by hand, and `resolution.h` no longer trusts a
  rank across lines. The other 11 ordinal-placed entries were checked one by
  one and held.

## Live run (throwaway Edge 157, `--user-data-dir` marker `edge157-live1`)

`[verify] msedge.dll 157.0.4341.42 (pinned 157.0.4341.42)`, status mode 0,
features 0xff, every hook `[ok]`, no fault. Driven through the control channel
and posted input to that window only: a 3-pane split (code 203) then a fourth
pane, swap, a pane's hover bar, the skin's tab frames and fonts, the find bar
with the options, RegExp, its flag switches, and a RegExp match found in the
page. Not driven: the hover card (needs the real mouse), link handlers, a
theme swap, reading mode, WebUI pages, tab drag, Ask Copilot.
